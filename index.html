HTML

CSS

Stage 2

The presentation layer, from the algorithm up. The cascade is a six-criterion sort with specificity fourth, and two of the three criteria above it — layers and scope proximity — are recent enough that most published advice predates them. Selectors including :has(), the value and unit system with its maths functions, custom properties and @property, the box model, flow, flexbox, grid and subgrid, positioning and anchor positioning, colour in the spaces browsers now compute in, typography, container queries, motion and view transitions, logical properties and accessibility, then architecture. Every number in it was measured in a real browser, and several contradict the widely published answer.

Assumes: you have written some CSS

SQL

Stage 3

The relational model, the query language, and then the system underneath it: how the planner turns a declarative query into a plan and how to read the plan back, what an index actually costs, and why MVCC makes a rollback cheap and a commit the expensive one. Testing

Stage 3

What a test is worth, rather than how to write one. The five kinds of test double and the two distinctions that actually decide anything; state versus behaviour verification, and why asserting that a query was called breaks on the next correct refactor; boundary analysis, decision tables and pairwise selection; design for testability, which is mostly the code reporting on itself. Then the levels: a real PostgreSQL started by the suite, HTTP APIs through a test client, contract tests that close the hole every double leaves, Testing Library against a DOM and Playwright against a real Chromium. Property-based testing, coverage and mutation testing — where 100% branch coverage still let ten of eighteen mutants live — flaky tests, the smell catalogue and the pipeline. Genuinely dual: every idea is taught in pytest and in a JavaScript runner, and every claimed output in the course was produced by running the tool, twice, and compared.

Assumes: Python, JavaScript
21 sections139k wordspytest 9 · Vitest 5 · Playwright 1.62

Stage 3

Then the three design techniques, flows and linear programming, number theory from Euclid to RSA, and what to do when a problem is intractable. Closes with randomisation and sketches, the algorithms underneath machine learning, and a capstone that builds a search engine from a dozen of them and prices every structure against the scan it replaces. Genuinely dual: every structure is given in Python 3.14 and in Node 24, and every measured claim in the course was produced by running the code, twice, and compared.

Assumes: Python, JavaScript
